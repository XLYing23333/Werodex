# Architecture

Local `werodex` reads a workspace config and speaks to local `werodexd` over a UID-checked Unix socket. The daemon controls SSH Master creation, connection backoff and channel leases. Connection identity hashes the effective hostname, port, user, identity files, ProxyJump and ProxyCommand. Source transfers use rsync over this SSH Master. Remote execution uses two daemon-held non-PTY channels connected to persistent Python 3.10+ workers in dedicated remote tmux sessions. Requests and stdout/stderr results are framed by UUID; remote operations do not launch an SSH client per command. No remote TCP listener or Codex installation is needed.

The shared PathPolicyEngine classifies paths as PROTECTED, IGNORED, LARGE, ARTIFACT or SOURCE. Automatic operations apply Protected > Werodex Exclude > `.gitignore` > Large > Source. Explicit `fetch` handles one Artifact file. A successful sync records a per-file size and SHA-256 baseline in `.werodex/state.json`. Conflicts compare both sides with that baseline and record Git HEAD, ancestry and dirty state in a report. mtime is never conflict truth.

Detached jobs run in tmux and write metadata plus rotated log segments under the remote user's `~/.local/state/werodex/jobs/<workspace-id>/`. The daemon can restart without terminating jobs and lists them from remote metadata after reconnecting. Logs enforce a live 256 MiB ring quota. Listing reads bounded metadata without a cleanup subprocess; owned completed jobs are pruned by hourly worker maintenance after their configured retention. Short commands also use the persistent tmux workers. One worker services normal control requests and the other blocking exec/wait; waiting happens remotely.

Git-dependent operations validate that the working-tree top level equals the project's real path. Shared local and remote guards reject parent repositories with `WDX_GIT_PARENT` and accept linked worktrees. Initialization performs read-only checks on both sides before creating Git or managed state.

PathPolicyEngine also excludes workspace rule files at every depth from both inventories and transfer approval. Old conflict reports are rejected when they name these files, and successful manifests drop their legacy baselines. Managed `.gitignore` changes remain a dedicated, block-only operation.

Work logs archive explicit local and remote attachments together, embed supported images and videos with relative references, and preserve fallback links and hashes. Recording milestones and inspecting visual evidence are agent instructions; ordinary sync never invokes an agent.

The default physical channel cap is three: two persistent control channels and one leased transfer/interactive channel. Limits of two and one reduce the control pool and serialize as needed. Leases count actual physical clients rather than whole logical sync operations. Target aliases share a pool when their effective SSH identity matches. Clients disable direct fallback with a failing ProxyCommand; only the daemon creates or reconnects a Master. Authentication errors pause and other failures use jittered backoff.

Daemon IPC authenticates once per persistent session, uses raw length-prefixed output frames with backpressure, and limits its global queue to 128 requests / 64 MiB input. Remote workers store bounded results for one hour, enabling explicit request-status recovery; disconnected writes are never automatically replayed. A daemon protocol upgrade stops only the verified local daemon and reconstructs its control channels; independent tmux jobs and Source baselines survive.

Checkpoints commit only named Source paths on both sides, store progress and per-side commit markers, and resume partial operations after revalidating content. Work logs check only explicitly declared Source, including deleted and renamed paths, and document when the remote could not be verified through an existing channel. Plans belong under `.werodex/plan/`; explicit migration prepares all link changes before mutation and rolls back failures.

Native tools, data boundaries and quotas: [NATIVE_TOOLS.md](NATIVE_TOOLS.md).

Source publication uses a per-workspace kernel `flock` held across scanning, transfer and Manifest updates; local native edits, checkpoints and restores share the lock. `.werodex/mutation.lock` records its owner PID/start time and must not be unlinked while a workspace is active. Kernel locks release when the owner closes its file descriptor or exits. Internal nested operations reuse the transaction context. Manifest writes also check the prior version.

Hash-selected rsync batches use `--ignore-times` and target `.werodex/transfer/<id>/incoming/`, never live Source. Python publishes staged regular files with Linux `renameat2`: no-replace for a new destination, exchange for an existing destination. Exchange retains the actual displaced inode, including an edit in the final rename window. Endpoint path/ignore policies and source hashes are checked before publication; unsupported atomic operations and cross-device renames fail closed. A destination mismatch reports a conflict and leaves the Manifest unchanged. If an edit occurs inside the exchange window, the incoming version may already be live; both versions are retained, and Werodex does not automatically overwrite the destination again.

Recovery snapshots and transaction metadata live locally under `.werodex/backup/<id>/{local,remote}/`. Published remote displaced files remain in remote staging until the local snapshot hash and durable metadata are verified. Interrupted or uncertain publications are inspected, never automatically repeated. `backup restore` first recovers any available displaced snapshot and refuses targets with subsequent changes. Failed archives preserve staging; unresolvable unknown states require inspection. Local backup and staging bytes count toward the existing local state quota; neither snapshots nor user logs are automatically garbage-collected.

Programs from CLI and MCP use the blocking lane. MCP queued programs do not consume file-operation slots. A bridge or tmux worker failure rebuilds only that lane over the existing Master; the healthy lane and independent jobs survive. Only a failed read-only Master check invokes connection-level backoff. Status includes per-lane health and availability. Clients awaiting exit still count against the physical channel budget. Limits of one and two preserve their serialized fallback behavior, with bounded adjustment/queue waits.

Checkpoint recovery validates both working content and Git history: recorded commits must remain ancestors of HEAD, the declared paths in HEAD must match the verified content, and that scope must have no staged or working changes. Later commits affecting unrelated paths are accepted. Legacy checkpoint records are checked by these same rules.
