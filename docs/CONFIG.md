# Workspace configuration

`werodex init` creates `.werodex/config.json`, `.werodex/review.json`, and a pending `.werodex/project-tree.md`; it does not sync or create a Sync Manifest. Fill the tree overview, mark data/output paths with `werodex exclude add PATH --reason TEXT`, and run `werodex review complete` before the first Source transfer. Existing workspaces with a successful Manifest remain approved. See `examples/config.example.json`. `workspaceId` identifies state and jobs; `remote.target` is an OpenSSH alias or hostname; `remote.project` is an absolute, specific project directory. `ssh.credentialRef` refers to the local Vault and is optional. `sync.delete` must remain false; `maxSourceFileMB` defaults to 32. `sync.exclude` accepts literal project-relative paths; `exclude add/remove` also maintains matching managed `.gitignore` blocks locally and remotely and `sync.excludeReasons`. Do not use glob characters. Code and documentation extensions bypass the default per-file Source size limit, while other files retain the `maxSourceFileMB` limit. There is no directory aggregate limit. Runtime defaults: `/tmp/werodex`, three channels, 256 MB of logs per job, seven days of retention.

`werodex config --credential-ref <id>` adds a Vault reference. Use `werodex credential init`, `credential set <id>`, `credential list`, and `credential delete <id>` from a terminal. Never put a password, private key or OpenAI token in config. `init` adds `.werodex/` to the repository-local Git exclude file; the PathPolicyEngine also excludes it from Source sync.

The optional `WERODEX_STATE_DIR` environment variable overrides the local daemon and ControlMaster state directory; an existing directory must be owned by the current UID with mode 0700; Werodex rejects a symlink or broader permissions. The remote job and conflict backup directories remain under the remote user's home.

The local `.werodex/logs/`, `.werodex/assets/`, and `.werodex/git-tree.md` are local-only state. `checkpoint -m MESSAGE -- PATH...` commits only named Source files in both repositories and returns both SHAs; partial operations resume with `checkpoint --resume ID`. New Git repositories use `main`.

`runtime.tmp` is an advisory temporary-output location for agents; it does not set a job working directory or `TMPDIR`. Jobs start in the remote project. Job metadata and logs live in the remote user state directory.

Source transfers validate both endpoints before writing. `WDX_TRANSFER_POLICY` means a candidate is ignored, protected, oversized or unsafe at an endpoint; inspect the rules or consistently exclude the path and retry. Git tracked status does not bypass ignore rules.

Both directories must be independent Git working-tree roots, including linked worktrees. `init` checks both boundaries before creating repositories or managed files. `WDX_GIT_PARENT` requires an explicit project-local repository before retrying; existing workspaces are checked during Source and Git operations too.

Rule files (`AGENTS.md`, `.gitignore`, `.ignore`, `.dockerignore`, `.rgignore`) at every level never participate in automatic Source operations, checkpoint, or conflict recovery. Exclusion commands maintain only the managed root `.gitignore` blocks; user content and permissions remain separate on each side.

`log add --file ENTRY.md [--asset REMOTE_PATH]... [--local-asset PATH]...` archives up to five combined attachments, each at most 32 MB, under `.werodex/assets/<work-day>/`. Local paths resolve against the workspace and are copied, not moved. Purely local logs need no SSH connection. Images are embedded in Markdown, MP4/WebM use HTML video plus a fallback link, and other formats use links. Record Source milestones with scoped finish and read-only milestones with log add; include changes, benefits, verification, next steps, and relevant visuals or a reason none applies. Run `review complete` to refresh the generated AGENTS instructions in an existing reviewed workspace.

`runtime.maxChannels` has an effective maximum of three; legacy values above three remain readable but are capped. Normally two persistent tmux control channels leave one channel for rsync or explicit interaction. Master connections persist until disconnect, daemon exit, or failure. `status.transport` exposes effective limits and connection/queue counters.

All plan Markdown belongs in `.werodex/plan/`, created by init/review complete. Use `plan migrate [--dry-run] -- .werodex/FILE.md...` for explicitly named legacy plans. `log add --source PATH` rejects uncommitted declared Source before saving assets or logs; an unavailable remote is explicitly UNVERIFIED and never triggers a new connection merely for logging.

Workspaces and aliases sharing one effective target share its physical channel budget. The smallest requested limit applies until explicit reconnect; increasing a configuration alone does not silently recreate channels. Summary `status` reads daemon state without initiating authentication and omits remote Git/job checks when no normal control channel is idle.

`runtime.maxLocalStateMB` optionally sets the logs/assets/cache budget (default 1024 MiB). `sync --full` refreshes the hash index. See [native tools](NATIVE_TOOLS.md) for MCP and streaming/cursor APIs.

`backup list` displays up to 200 local transaction records. `backup restore ID --side local|remote -- PATH...` restores explicitly selected displaced Source versions, after verifying their hashes and that the destination still matches the version published by that transaction. The command creates its own recovery snapshot. Remote restore requires a connection; local restore is offline for locally published transactions. An interrupted archive is recovered from staging before restore when available. Legacy `conflict restore` remains available; new conflict resolutions use local snapshots.

Snapshots use `.werodex/backup/<transaction-id>/`, with 0700 directories and 0600 files. The existing `runtime.maxLocalStateMB` quota includes backup and transfer staging. Quota failures abort safely and may leave a pending recovery transaction if publication already occurred. `storage gc --apply` deletes only cache files, not backup or staging. Archive recovery files explicitly when no longer needed. Local mutations require the Linux `flock` utility; atomic publication requires filesystem support for Linux `renameat2`.

Transaction preparation adds `.werodex/` to each endpoint's repository-local `info/exclude` when missing, preserving existing rules; it does not sync or replace workspace `.gitignore` files. This keeps temporary recovery state out of Git status and commits.
